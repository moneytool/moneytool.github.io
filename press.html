Long about 120 words

Vamshidher Reddy Jannapu Reddy is an independent researcher in Austin, Texas, who builds guardrails for AI agents that act on real cloud and Kubernetes infrastructure, after more than ten years running Kubernetes, Terraform, CI/CD and AWS in production. The work asks a question most agent guardrails skip: who wrote a policy rule, and did that person have the authority to make it? Jannapu Reddy created and maintains Aegis-DevOps, an open-source verifier that checks a rule's source and its author's authority before an agent's action runs. Two other open-source tools, agentmeld and ecsodus, keep coding-agent configuration consistent and move AWS Copilot CLI applications to Terraform. Jannapu Reddy has had 11 pull requests merged into open-source infrastructure projects from AWS, CNCF, Anchore and Mend.

Topics I can comment on

  • Guardrails for AI coding agents that run commands against cloud and Kubernetes infrastructure
  • Where policy rules come from: who wrote a rule, and whether they had the authority to make it
  • When an agent should act on its own and when it should stop and ask a person
  • Kubernetes admission policies and AWS Service Control Policies as places to enforce rules

Quotes you can use

“Most guardrails for AI agents look at the command. Very few look at the rule that allowed it. If a rule was copied out of a ticket or a chat thread, someone should be able to say who wrote it and whether they were allowed to.”

Vamshidher Reddy Jannapu Reddy

“A useful test for any team using coding agents: if the agent deletes something in production, can you show which rule allowed it and who wrote that rule? I suspect most teams cannot answer that yet.”

Vamshidher Reddy Jannapu Reddy

“Reading pods is fine. Running terraform apply should usually wait for a person. Deleting a production namespace should be blocked. Most people agree on those three cases. The hard part is keeping the rules behind them honest as the list grows.”

Vamshidher Reddy Jannapu Reddy
